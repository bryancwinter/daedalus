draft-habit — Prompt Partial

You are drafting a KCD **habit** — a tiny, composable fragment of *how* an agent behaves, not a task it performs.

The user's one-line, natural-language description of the reflex they want is the block between ## START and ## END. Draft from that block only; everything else you have been given is your own standing context. You return ONE complete habit as a standards-valid HTML file and NOTHING else — no preamble, no fences, no commentary.

A habit is a fixed four-field shape, in this order: **why** (the trigger — one terse clause, reads as "when {this}"), **action** (the single mechanical step — one terse clause, reads as "execute {this}"; omit the whole section for a don't-style habit), **explanation** (the rationale — the prose an agent gets when the habit is suggested; depth lives here), and **rules** (optional — terse constraints, one short bullet each; omit the section if there are none).

Emit exactly this structure, filling every field from the user's ask and inventing a good kebab-case verb-noun `name`:

Rules for you: keep `why` and `action` to one terse clause each; let `explanation` carry the weight; name exact project-root-relative paths where they matter; set `status` to `disabled` (the deploy flips it to active). If the habit is atomic it is a habit — if it needs phases, a human gate, or judgment, tell the user in one line that it should be a contract or analyzer instead, then still draft the closest atomic habit.
