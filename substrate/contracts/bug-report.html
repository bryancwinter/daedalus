Bug Report — Contract

Open the door, do the work, close the door behind you — and leave a record that proves it.

When

Invoked explicitly as #bug-report, or by description — "file a bug for this", "pick up bug 14". A report is for a real bug that needs repair and is complex enough to need investigation. A bug that can be fixed inline is fixed inline, and a bug already known to be fixed is not reported at all.

A report is what a known defect becomes instead of a todo. It is useful but ephemeral — not a ticket history. The code keeps moving, so a report is a claim about how the code was when it was filed, and it is checked against the code as it is now before anyone acts on it.

It is multi-stage by design. Filing is a complete use of the contract on its own: a report can sit open for weeks before anyone claims it, and the agent that repairs it need not be the one that found it — or even run in the same host.

The record serves two readers. The agent doing the work uses it to orient itself. Every other agent uses it to learn that something moved under them.

Artifact Format

One file per bug, of type bug-report, at _Claude/bug-reports/bug-report-{n}.html. The ID is a plain increment: one past the highest number on disk.

Status — the task board's own words: queued → working → verified, or rejected when it is not a bug or no longer reproduces. needs-human is the one addition: an agent could not settle it. A report the human sends back returns to queued.

Fields map onto the board by name. Every value a board task carries is an annotated field — <span data-kcd-field="assignee" data-kcd-type="text">main</span> — and the field name is the Task property, spelled exactly. Write them inline in the prose of the section that owns them; nothing else about the prose is constrained.

WhereFields
frontmattername · description ( the bug in one line, the task's title ) · status · created · updated
ReportraisedBy ( text — who filed it ) · priority ( enum — low, medium, high, critical ) · exitCondition ( text — what is true once fixed )
Repairassignee ( text — the claimant ) · startedAt ( date )
VerificationverifiedBy ( text — the signer ) · approval ( enum — self when the repairer signs its own work; omitted otherwise ) · endedAt ( date )

Sections:

  • Report — the symptom, how to reproduce it, where it lives, and any recorded evidence of the failure, quoted rather than paraphrased.
  • Door — the trace areas this agent armed, and a closing line once it disarmed them. none when no trace was used.
  • Repair — what moved: the files, the behaviour, and why.
  • Proof — the evidence before and after, or a plain statement that the fix could not be confirmed and why.
  • Verification — who signed it, or the question the human is being asked.
  • Notes — anything else a later reader needs.

Names: an agent signs with the name its host gives it — a constellation seat, a board agent, or a plain session's lens.

Pointing at a report: bug-reports/ is ephemeral space, so a document that names a report does so with an address — <code data-kcd-address>_Claude/bug-reports/bug-report-14.html</code> — never an <a href>, which the validator refuses.

Not yet on the board, kept for the rationalizing pass: verifiedBy has no Task twin, a verifier other than the repairer has no approval word, and needs-human is expressed on the board as an ask raised against the task rather than as a state.

Lifecycle

Eight phases. Phase 1 stands alone; Phases 2–8 run together once a report is claimed.

Phase 1 — File

Trigger: the human asks for a bug to be filed, or an agent finds a real defect that needs investigation and is not fixing it now.

Together: The agent takes the next ID, writes the Report with its raisedBy, priority and exitCondition, and sets status to queued. A defect goes here, not onto the todo list.

Standard: An agent with none of this session's context can find the bug from the Report alone.

Phase 2 — Claim

Trigger: an agent takes up a queued report.

Together: It sets status to working and writes assignee and startedAt into Repair before touching anything.

Standard: One claimant at a time. A report claimed by another agent is not taken over. The claimant reads the Report as a claim and checks it against the code as it is now — it may have drifted, or already be fixed.

Phase 3 — Open the door

Trigger: the project has a trace instrument that reaches the bug.

Together: Per the trace-door habit — read what is already recorded, see what is already armed, arm only what this bug needs, and write that list into Door before reproducing.

Standard: Door is written before the first reproduction. With no instrument, Door reads none and the contract carries on — the trace is a guide, never a gate.

Phase 4 — Reproduce

Trigger: always, once claimed.

Together: The agent reproduces the failure and puts the before evidence into Proof.

Standard: The before evidence shows the failure. If it will not reproduce, Proof says so and the agent decides whether to carry on or set needs-human.

Phase 5 — Repair

Trigger: always, once reproduced or knowingly not.

Together: The agent fixes the bug and writes Repair. This contract adds no stop of its own; a human-driven session still drafts and explains before code, per the entry document's hard rules.

Standard: An agent working elsewhere learns from Repair alone what changed under it.

Phase 6 — Prove

Trigger: always, once repaired.

Together: The same door and the same reproduction again; the after evidence goes into Proof beside the before. Changed behaviour is also covered by a test, per the project's own testing habit where it has one. Where there is no way to confirm the fix, Proof says so plainly and status becomes needs-human.

Standard: Before and after, read side by side, settle it. The after evidence shows the fixed path running — an absence of failure lines proves nothing, because code that never ran leaves none either.

Phase 7 — Close the door

Trigger: Door lists anything.

Together: Per trace-door, the agent disarms exactly what Door lists and writes the closing line.

Standard: Nothing this agent armed is left armed; nothing it did not arm is touched.

Phase 8 — Verify

Trigger: Proof settles it.

Together: The verifier writes verifiedBy, approval as self when it is the repairer, and endedAt, then sets status to verified. A verifier that cannot make a reasonable judgment sets needs-human instead and writes its question into Verification.

Standard: Verification is a signature on the proof, not a grade. It is light on purpose.

Standards

  • Proof, not ceremony. The record exists so the fix can be confirmed quickly. A field that does not help an agent orient or a reader confirm does not belong in it.
  • Humans never sign. verifiedBy is always an agent. The human spot-checks verified reports and returns any that are wrong to queued.
  • The escape path is always open. Any phase may end in needs-human with the question written down. That is a finished use of the contract, not a failure of it.
  • A needs-human report does not move until the human rules in writing to an agent. The human never edits the record. The agent it told writes the ruling into Verification as a note, attributed and dated, and moves status as the ruling says.
  • Reports are ephemeral. Verified and rejected reports sit until the monthly sweep, where the human approves their deletion. No agent deletes one on its own, and nothing depends on a report outliving that sweep.
  • Route, never restate. How to arm and disarm lives in trace-door and the project's trace reference; how to cover a change lives in the project's testing habit. This contract carries only order and the record.

Edge Cases

  • Proof fails. Back to Phase 5 with the door still open. The door closes once, at the end.
  • The agent dies mid-repair. Door names what is still armed, so whoever picks the report up next closes that door before opening its own.
  • Sent back to queued. The Report stays. The next claimant writes Door, Repair, Proof and Verification afresh rather than appending to the last attempt's, and says in Notes what the previous attempt got wrong.
  • The bug is already gone, or was never one. Proof records why, and status becomes rejected — never deleted unrecorded.

Scope Values

universal — referenced from _lens-base, so any session can file or pick up a bug.
