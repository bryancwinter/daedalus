log-action — Habit

Why

the user asks to "log" / "do the logging", or a session closes after work changed <code>_Claude/</code> or the codebase

Action

Call <code>sm_log__log_action</code> with the active <strong>lens</strong>, a one-line <strong>note</strong> saying what happened, and a <strong>detail</strong> when there is more than the line can hold. Never open a file to do this.

Explanation

A LOG ENTRY IS A CALL, NOT A FILE HANDLE, and that is the whole of this habit. The record is a table behind a program that serializes writers, so a row is inserted or it is not. What it replaced was a shared Markdown file several lanes wrote at once: an entry written at midday on 2026-09-12 was gone by 13:29, taken out by another lane's whole-file write, and it was noticed only because the session that wrote it came back hours later and grepped for its own words. An append-only convention lowered the odds of that and closed nothing, because nothing detects a lost entry.

IT IS AN ACTION LOG, NOT A SESSION LOG. The entry says that something happened. It names the lens and, if you have one, your own name — and it carries no session, deliberately. A session is a thing that gets destroyed; what was done outlives it.

WRITE THE FINDING, NOT THE ACTIVITY. "Audited the colour tokens" tells a future reader nothing they can act on. "The severity system had never once repointed anywhere in the app" is the same session's work and is worth the line. The note is what a search returns and what somebody skimming a month will read; the detail is where the reasoning, the ruling and the rejected alternative go.

NOTHING CAN EDIT OR DELETE AN ENTRY AFTERWARDS, and no tool exists that will — an editable log is a record that can be made to agree with whoever read it last. Say it right the first time. If you got it wrong, log a second entry saying so; that is a truer record than a corrected one.

Read the log back with sm_log__find_actions — by keyword, by lens, by date window. The search errs towards too many results on purpose, so skim rather than typing more precisely. A person reaches the same two tools through the Action Log studio plug-in.

Rules

  • one entry per session, checkpoint, or task-agent's work — never per edit
  • the note is ONE line, roughly 40 words; anything longer belongs in the detail
  • the lens is the active lens name; use a descriptive tag for cross-cutting work
  • never hand-write to a log file; if the tool is unreachable, say so rather than routing around it
