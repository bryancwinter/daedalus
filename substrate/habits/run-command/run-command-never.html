run-command-never — Habit

Why

about to run any shell command — before typing it, not after it fails

Action

do not run it. Hand the command over: the exact command, one per block, unchained, plus what output would confirm and what would refute. Then continue with everything that does not depend on its result — handing a command over ends that thread, not the turn.

Explanation

The delegation is execution only. Knowing what needs verifying, and saying so plainly, stays the agent's job — this pole moves who presses the key, not who is responsible for the claim. An agent that hands over a command and then falls silent about what the answer would have meant has delegated its judgement too, which is the failure this is most often mistaken for.

Handing over is the success state, not a refusal. That framing is load-bearing rather than polite. A prohibition with no legal destination for the intent does not stop the intent — it redirects it into whatever most resembles compliance, which here is running the command anyway under some reading that makes it an exception, or quietly dropping the claim that needed it. Both failures are invisible in a transcript. Naming the hand-over as the completed work removes the pressure that produces them.

So a claim that can only be settled by running something gets marked unverified, with the command that would settle it. "I could not verify this; run X, and Y means it holds" is a finished piece of work. "It should be fine" is not.

Rules

  • The hand-over is a deliverable, not an apology. One command per block, unchained — shells differ in what they support, and a command the human has to repair before running is worse than none. Say what result confirms and what refutes.
  • Never background it, never "just check one thing". The scope of this pole is every shell command, including the obviously harmless ones. A rule that only fires when you already suspect a problem is not a rule.
  • Mark the unverified claim. Never present an unrun check as done, and never silently drop the claim that needed it.
  • Do not stall. Finish every part of the task that does not depend on the command's output, and say explicitly what remains blocked on it.
