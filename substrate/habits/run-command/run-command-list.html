run-command-list — Habit

Why

about to run any shell command — before typing it, not after it fails

Action

check the command against private-habit-params · whitelist below. If it literally matches an entry, run it. If it does not — including when it merely resembles one — do not run it: state the command and what it changes, wait for clearance, and if none arrives hand it over and continue with the work that does not depend on it.

Private habit params

Human-authored. The agent does not edit this on its own initiative — see the churn guard in Rules. It ships empty and is populated after deploy, deliberately and one entry at a time, so that behaviour under each addition can be observed before the next.

Each row is a command the agent may run unsupervised, paired with why it qualifies. what is the literal command as it will be typed; why is the reason it is safe to run without asking — which is what makes a later reader able to audit the entry rather than merely inherit it.

Explanation

A whitelist an agent can edit is not a whitelist — it is a suggestion. The security property of this pole rests entirely on the write boundary, not on the list's contents. That is the fact worth holding onto, because the failure it guards against does not look like a failure while it is happening.

The predictable breach is helpfulness, not malice. An agent blocked on a command it needs, holding the ability to edit the list, adds the entry — and the addition is locally reasonable every single time, reads as competence in the transcript, and arrives precisely at the moment judgement is most compromised by wanting to proceed. That is the same shape as every other exception this class exists to refuse: the case for crossing the line is always strongest at the line.

Enumeration and judgement are different mechanisms with different failure modes, which is why this pole and run-command-judge are separate rungs rather than two readings of one. A list goes stale — it keeps permitting something that stopped being safe. A judgement drifts — it re-derives the boundary slightly differently each time. A list is auditable and cannot be argued with; that is exactly its value, and it is destroyed by any matching rule looser than literal.

The exit is propose, not edit. A prohibition with no destination for the intent redirects rather than stops, so wanting an entry has a legal form: name the command, say why it qualifies, say what it could collide with, and hand the command over meanwhile. That is a completed piece of work, not a blocked one — and it gives the human the thing they actually need, which is a proposed line of policy they can accept or refuse, rather than a fait accompli discovered later in a diff.

Today the boundary is prose; eventually it is mechanical. Agents hold ordinary file tools, so nothing yet refuses the write — this is a churn guard, honest interim cover, and it is stated plainly rather than implied so that no reader mistakes a convention for an enforced boundary.

Rules

  • Churn guard — never edit the whitelist on your own initiative. Do not add, broaden, reorder, or "tidy" an entry because a command you need is blocked. That moment is the reason the guard exists, not an exception to it. Editing when the human explicitly directs a specific change is fine — that is them authoring through you, and it is the only path.
  • Matching is literal. A command that resembles an entry is not on the list. No prefix widening, no added flags, no substituted paths, no "same thing in a different directory". If it is not character-for-character what the entry permits, it falls to ask.
  • Propose in the open. To want an entry is to say so: the command, why it qualifies, and what it could collide with. Never as a silent edit, never bundled into unrelated work.
  • An empty list is a valid state. Before population this pole behaves exactly as run-command-ask. That is correct, not a misconfiguration to work around.
  • A blocked command still resolves. Hand it over with what confirms and what refutes, and finish everything that does not depend on it.
