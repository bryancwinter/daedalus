trace-door

Open the door, do the work, close the door behind you.

Why

about to arm a trace area, or about to reproduce, investigate or confirm a runtime defect in a project whose trace instrument has areas that are switched on and off — whether or not a bug report is open for it

Action

read what the trace has already recorded before arming anything; read which areas are already armed; add only the areas this work needs, and write down the ones you added — into the Door section of the bug report being worked, or into the reply when there is none; reproduce only once the arming has taken effect; read the output; then remove exactly the areas you added and say so. How this project's instrument does each step lives in its trace reference — find it with kcd_query when the active lens does not carry it

Explanation

A trace instrument is shared state. Several agents can be working against the same running app at once, each with areas armed for its own problem, so every change to the armed set lands on all of them. That is why arming is additive and disarming is exact: an agent that replaces the whole set, or clears a channel to get a clean read, has switched off another agent's evidence or destroyed it, and that agent gets no signal that anything happened.

The record comes before the theory. Most instruments log failures whether or not anything is armed, so the reason for a defect is often already written down before any area is switched on. Reading it first is cheaper than arming, and it keeps an agent from building an explanation that the record already contradicts.

A line is written only when its area is armed at the moment the code runs. Arming after reproducing, or before the arming has propagated, produces an empty read — and an empty read looks exactly like a clean one. Silence is not evidence: code that never ran leaves no failure lines either, so a confirming read has to show the path running, not merely the absence of errors.

Writing down what you armed is what lets the door be closed by someone else. An agent can be interrupted, compacted or killed mid-work; the note tells whoever comes next what is still armed and whose it was.

The trace is a guide, not a gate. It exists to make a fix checkable, and an agent that cannot use one — because none exists, or it does not reach the failure — carries on with whatever other evidence it has and states plainly how far that evidence goes.

Rules

  • never replace the whole armed set — add and remove single areas only; a replace silently switches off every other agent's areas
  • never clear or truncate a trace channel — narrow the read with a search instead; a cleared channel may hold another agent's only evidence
  • never remove an area you did not add, even one that looks abandoned — name it in the reply and leave it
  • an area someone else already armed can be read freely, but it is not yours to note or to remove
  • a reply that does not confirm an area as armed means it is not armed — correct the name and arm again before reproducing
  • never report a fix as confirmed from an empty read — find a line, receipt or record showing the fixed path actually ran
  • close the door before reporting the work done; when a disarm fails or the instrument is unreachable, say exactly what is still armed
  • when there is no trace, or it does not reach the failure, say so and continue with other evidence — and when nothing can confirm the fix, say it is unconfirmed and ask for human review rather than calling it fixed
