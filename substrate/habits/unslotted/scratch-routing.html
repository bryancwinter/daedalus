scratch-routing — Habit

The sibling of work-routing. That habit routes what a session produces; this one routes what a session leaves behind. The two failures are different: misfiling a document puts it in the wrong folder, while a byproduct written to a host-supplied temp path leaves the vault entirely — where nothing this project builds can see, review, sweep, or eventually sandbox it.

Why

about to write a file that is not the deliverable — a temp file, an intermediate dump, redirected command output, an extracted payload, a downloaded blob, or a one-off script written only to get through this turn — or about to reach for a path the harness or the OS supplied ( a scratchpad directory, /tmp, %TEMP%, os.tmpdir() ) rather than one chosen from this vault

Action

write it under _Claude/work/{lens}/AI/scratch/ — the whole path from root, {lens} the primary lens — and when a tool can only write outside the vault, name that path in the reply rather than letting the write pass unmentioned

Explanation

A byproduct written to a host-supplied temp directory lands outside everything this project can reach: not in the vault the tooling scans, not in a repo anyone reviews, and at a path that changes between hosts and sessions, so nothing can locate it again. It also bypasses the one gate that exists — the harness pre-authorizes its own scratchpad, so a write there never meets the approval that write-files-scoped would require anywhere else outside _Claude/. This habit does not enforce a boundary and does not sandbox anything; it makes a boundary possible later by giving every byproduct one location the project owns. That location is also the cheap route — writes inside _Claude/ are already pre-approved, so complying costs no approval round-trip. Scratch stays liberal: this governs placement and visibility, never permission to build. The separate scratch/ folder is what makes the pile safe to flush — its contents are known-disposable by construction, so a sweep needs no judgment about any individual file, which is not true of AI/ proper.

Rules

  • never write to a harness- or OS-supplied temp path ( a scratchpad directory, /tmp, %TEMP%, os.tmpdir() ) — a file there is unreviewable, ungoverned, and unfindable next session
  • never drop a loose file at a repo root or the working directory — that is scratch that escaped; it belongs under AI/scratch/
  • write the whole path from root every time, and {lens} is the primary ( first-loaded ) lens — the same owner rule as work-routing, with no scratch/cross/
  • never cite scratch back as authority — it is unreviewed byproduct, so if a fact inside it matters, re-derive it from the source that produced it
  • when an external tool can only write outside the vault, say so and name the path — an unmentioned out-of-vault write is the exact failure this habit exists to stop
  • route rather than absorb: a script that interrogates a repo's own code is author-script's scripts/probes/, and a document the user will read is work-routing's AI/ — scratch is only what nobody will read
  • when the output only needs reading once, read it from the command and write no file at all
