log-session-liberal — Habit

Why

the user asks to "log" / "do the logging", or a session closes after work changed _Claude/

Action

APPEND one dated breadcrumb line (format YYYY-MM-DD : {lens} : note.) to the FOOT of _Claude/logs/session.md — never prepend, never rewrite the file

Explanation

The session log is a terse, scannable trail of pointers — a breadcrumb, not a changelog. A task agent asked to log appends exactly one line for its own work — no completed entry, no pruning; the detailed record is the completed log's job, not this one's. Compacting is a future, eventually-automated concern, not a standing cap.

APPEND, NOT PREPEND — because agents clobber each other and nothing detects it ( Bryan's ruling, 2026-09-12 ). Newest-on-top means every writer rewrites the WHOLE file, and several lanes run at once by design: an entry written at midday on 2026-09-12 was gone by 13:29, taken out by another lane's whole-file write, and it was noticed only because the session that wrote it happened to come back hours later and grep for its own words. The failure is silent and unbounded — nothing compares before and after, and a lane that logs once and exits never learns. An append touches only the end of the file, so two lanes writing in the same minute cost at most an interleaving rather than a deletion. The read path is tail, which is why the newest entry belongs at the foot.

This is the INTERIM fix. The durable one is a program rather than a file handle — a tool that takes one entry and never the file — raised on the vault lens's todo.

Rules

  • one line, ≤ ~40 words — no bold, headers, nested bullets, or file-link dumps
  • one entry per session, checkpoint, or task-agent's work — never micro-edits
  • {lens} is the active lens name; use lens-crafter or a descriptive tag for cross-cutting work
